# M11 - Design win: charter, evaluation, feature request, win plan (1 hour)

**A PoC is won before it starts: agree on criteria that each have a measuring tool, then report in the customer's unit,
dollars per 1,000 disruptions.** Tern Travel Group and its people are fictional; the documents are the ones you will
write on a real account.

| File | When you use it |
|---|---|
| [discovery-questions.md](discovery-questions.md) | M1: 30 questions by stakeholder, each with why we ask |
| [poc-charter.md](poc-charter.md) | before the PoC: scope, 10 criteria mapped to tools, roles, exit, sign-off |
| [mutual-action-plan.md](mutual-action-plan.md) | the whole way: owners on both sides, ending in production |
| [technical-win-plan.md](technical-win-plan.md) | internal: account map, proof points, competition, risks |
| [poc-evaluation-report.md](poc-evaluation-report.md) | after M10: results against the charter, recommendation |
| [feature-request.md](feature-request.md) | product feedback: prefix-cache accounting per agent session |

## Steps
1. Read the charter's criteria and find the tool behind each one in this repo. Run one of them on the mock.
2. After M10, fill the evaluation report from `results/` only, with the file next to every number.
3. Fill the feature request's `[measured]` rows from drill 1 on the GPU.
4. Update the win plan: which proof points do you now have, and which risk moved?
5. Practise the readout from [docs/09](../docs/09-results-and-exec-readout.md) section 6 in 5 minutes.

**Checkpoint:** you can map every charter criterion to its tool in under 2 minutes, and your feature request names a
measured impact and testable acceptance criteria.

**Say it:** "We agreed on ten criteria and the tool that measures each one before we started, so the readout is a set
of measurements, not an opinion."

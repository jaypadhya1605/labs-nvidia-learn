Azure SE → NVIDIA SA translation map

Start every NVIDIA answer from an Azure concept you've already sold and deployed. Then name the difference: on NVIDIA, you own the GPU.
As an Azure SE, I know…NVIDIA equivalentThe difference to say out loudLab
Foundry model deployment (serverless, PTU)NIM: model container with an OpenAI-compatible APISelf-hosted: you choose the GPU, the profile and the uptime. NIM picks an optimized engine profile per GPU, so check which one it chose.P1→P3
TPM / PTU capacity planningGPU sizing: tokens/s per GPU; VRAM = weights + KV cacheHosted: TPM counts max_tokens (the AI-Q 429 lesson). On a GPU, KV-cache memory is what limits concurrency.P2·P3
AKS GPU node pool (managed driver + device plugin)GPU Operator: driver, container toolkit, device plugin, DCGM, MIG managerUse one GPU manager, not two. The lab uses AKS-managed drivers and does not install GPU Operator.P3
No direct Azure equivalentNIM Operator: NIMCache + NIMService CRDsManages the model and its cache, not the GPU. The 21 GB cache on emptyDir moves to a PVC so restarts are fast.P3
Azure ML online endpointTriton Inference Server: multi-framework, dynamic batching, ensembles, metricsTriton is the serving layer. The TRT-LLM backend runs LLMs inside it.P4
ONNX Runtime / Olive optimizationTensorRT-LLM: optimized kernels, in-flight batching, paged KV, FP8/FP4An engine, not a server. Serve it with trtllm-serve or Triton. Precision depends on the GPU generation.P4
APIM AI gateway (load-balance, token limits)Dynamo (KV-aware routing, disaggregated prefill/decode) · Switchyard (model routing)APIM routes HTTP. Dynamo routes by KV-cache state across engine workers. Switchyard escalates to bigger models only when needed.P4*
Content Safety / Prompt ShieldsNeMo Guardrails: input, retrieval and output rails (Colang)Programmable and self-hosted. Still not proof of HIPAA compliance or access control.P2·P5
Azure AI Search (hybrid / vector)NeMo Retriever embedding + rerank NIMs · cuVSThe lab keeps AI Search as the index and uses nemotron-3-embed-1b (2048-d) for AI-Q.P2
Foundry Agent Service / Semantic KernelAI-Q blueprint + NeMo Agent ToolkitBlueprints are starting points. AI-Q needed an Entra token proxy and call budgets before it was usable here.P2
Foundry evals + App Insights tracesAIPerf (TTFT/ITL load) · NeMo Evaluator · DCGMKeep endpoint speed and answer quality as separate measurements. GenAI-Perf is being phased out; AIPerf replaces it.P2·P4
Azure ML fine-tuningNeMo Customizer / NeMo framework LoRAThe adapter must match the base model and the serving engine's LoRA support.P4*
VM SKUs: NC A100 v4 · ND H100 v5GPU generations: Ampere A100 · Hopper H100 (FP8) · Blackwell (FP4)A100 has no native FP8/FP4, so the lab's FP8/FP4 weights ran weight-only through Marlin kernels.P3
Pattern for any NVIDIA question: “On Azure I'd use X. The NVIDIA building block is Y. The trade-off is control vs. operations: you gain latency, cost-per-token and data control, and you take on sizing, patching and uptime.”  * = conditional track
